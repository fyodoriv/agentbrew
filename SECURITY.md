# Security Policy

## Supported Versions

| Version | Supported          |
| ------- | ------------------ |
| latest  | :white_check_mark: |

Only the latest published version of agentbrew receives security updates.

## Reporting a Vulnerability

If you discover a security vulnerability in agentbrew, please report it responsibly:

1. **Do NOT open a public issue.** Security vulnerabilities must be reported privately.
2. **Use GitHub Security Advisories**: Go to [Security Advisories](https://github.com/fyodoriv/agentbrew/security/advisories/new) and create a new advisory.
3. **Or email**: Send details to **opensource@example.com** with the subject line "agentbrew security vulnerability".

### What to include

- A description of the vulnerability
- Steps to reproduce
- Impact assessment (what an attacker could do)
- Suggested fix (if you have one)

### Response timeline

- **Acknowledgment**: Within 2 business days
- **Initial assessment**: Within 5 business days
- **Fix release**: Depends on severity, typically within 30 days for critical issues

### What happens next

- We will confirm receipt and begin investigation
- We will keep you informed of progress
- Once fixed, we will credit you in the release notes (unless you prefer to remain anonymous)
- We follow [coordinated disclosure](https://en.wikipedia.org/wiki/Coordinated_vulnerability_disclosure) — we ask that you do not disclose publicly until a fix is available

## Scope

This policy covers the agentbrew CLI tool and its published npm package. It does not cover:
- Third-party MCP servers installed via agentbrew
- Skills from external sources
- Agent configurations generated by agentbrew (those are owned by the respective agent tools)

## Privacy contract

`github.com/fyodoriv/agentbrew` (branch `main`) is the only canonical home.
It is public. The repo has a strict **no-leak** contract: no details of
private internal infrastructure, no hardcoded secrets, and no private
email identities may ever reach it.

### Contract

Three independent leak categories are blocked:

1. **Content leaks** — configured private identifiers in tracked files (company
   names, internal product names, internal org prefixes, internal hostnames,
   Jira project codes). Source of truth: `OSS_READINESS_INTERNAL_PATTERN` in
   the org overlay's `oss-readiness.env`. The check lives in
   [`src/oss/no-internal-refs.test.ts`](src/oss/no-internal-refs.test.ts).

2. **Identity leaks** — git commits authored or committed by a private
   email. These appear in `git log` and identify both the company and the
   person. Source of truth: `OSS_READINESS_PRIVATE_EMAIL_PATTERN` in the org
   overlay's `oss-readiness.env`.

3. **Secret leaks** — hardcoded API keys, OAuth tokens, AWS keys,
   private keys. Caught by:
   - GitHub secret scanning, and gitleaks in `.github/workflows/ci.yml`.
   - `~/apps/tooling/dotfiles/git-hooks/pre-commit` when `core.hooksPath`
     points at the dotfiles repo's hooks (recommended for any host that
     contributes).

### Gates (defense in depth)

| Layer | Where | What it catches |
|-------|-------|-----------------|
| **L1** Secret scanning | GitHub secret scanning; gitleaks in `.github/workflows/ci.yml` | Secret-shaped tokens |
| **L2** Pre-commit hook | `~/apps/tooling/dotfiles/git-hooks/pre-commit` (global) | Content + secret + author-email on staged files (when wired) |
| **L3** Pre-push hook | `~/apps/tooling/dotfiles/git-hooks/pre-push` (global) | Blocks a push to `github.com/fyodoriv/agentbrew` when any author or committer email matches the private-email pattern |
| **L4** CI (GitHub Actions) | `.github/workflows/oss-readiness.yml` | Runs the no-internal-refs test and a private-email check on every PR |

GitHub Actions is disabled on `fyodoriv/agentbrew` today. The CI layers do
not run. `npm run verify` is the local gate: it runs the no-internal-refs
test, `scripts/lint-security.sh`, and the full test suite. Run it before
every push.

### Private emails are blocked, never rewritten

There is no mailmap and no history rewrite. A private email can never be
made safe by mapping it: the original commits still carry it.

- Set a public-safe `user.email` before you commit (see below).
- If an unpushed commit carries a private email, fix it locally before you
  push. For the last commit: `git commit --amend --reset-author --no-edit`.
- The pre-push hook names each blocked email and stops the push. It never
  lets a private email through.

### How to commit safely

Every dev should set `user.email` to a public-safe address in this repo:

```
git -C ~/apps/tooling/agentbrew config user.email <your-public@email>
```

### Allowlisted configured private references

A small set of files may mention the configured private identifiers. They are
historical (CHANGELOG, TASKS) or describe the team overlay feature (README,
AGENTS.md, VISION.md). The full list lives in
`src/oss/no-internal-refs.test.ts`'s `PERMANENT_ALLOWLIST` set, with one
justification comment per entry.

### Why this design

- **Block, don't rewrite** — a mapped email still sits in the original
  commits and in every clone. Blocking at push time is the only safe fix.
- **All failures are loud** — hook rejection, vitest failure, and
  secret-scan hits all print to stderr. No silent leakage.
