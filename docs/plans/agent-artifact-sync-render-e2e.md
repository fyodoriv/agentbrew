# Plan: agent-artifact-sync-render-e2e

## Goal
Extend real end-to-end coverage beyond commands so the production sync/render surfaces for instructions, rules, agents, hooks, and MCP config are exercised in a temporary HOME and verified through `sync --only <surface> --sequential` plus `status --fix`.

## Why
Unit and matrix tests pin renderer details, but they do not prove the full CLI path writes parseable files into real agent home locations or repairs missing managed output without deleting user-owned files. The existing commands real-e2e scenario caught that class for command sync; the remaining high-impact agent surfaces need the same deterministic sandbox coverage to support VISION.md G5/G6 drift-repair and primary-agent parity.

## Scope (in)
- Add small real-e2e scenarios for non-command surfaces:
  - instructions
  - rules
  - agents
  - hooks
  - MCP config
- Use temporary HOME fixtures, `seedScenarioState`, `agentbrew sync --only <surface> --sequential`, and `agentbrew status --fix`.
- Assert structural content, parseability where applicable, managed missing-file repair, and preservation of user-owned local files.
- Keep selected-run support aligned with the task's requested command shape.
- Update README or scenario map only when the runnable command or coverage map changes.

## Scope (out)
- Does not rewrite sync engines unless a scenario exposes a real bug.
- Does not snapshot full generated prompts or large config payloads.
- Does not add live external MCP probes or networked integration checks.
- Does not attempt to cover every long-tail agent path; the first PR focuses on primary-agent/carve-out outputs that are deterministic under a sandboxed HOME.
- Does not depend on the unmerged `agent-artifact-inventory-static-gate` PR.

## Implementation steps

1. Inspect existing real-e2e fixture shape:
   - `real-e2e/scenarios/us05-us06-commands-and-drift.test.ts`
   - `real-e2e/scenarios/us04-share-rules.test.ts`
   - `real-e2e/scenarios/us21-shell-hooks.test.ts`
   - `src/real-e2e/scenario-fixture.ts`
   - `src/real-e2e/selected-runs.ts`

2. Improve selected-run ergonomics if needed:
   - Make `npm run test:real-e2e:selected -- instructions rules agents hooks mcp` resolve tokens to the matching new scenario files.
   - Keep existing explicit-path selected runs working.
   - Add focused tests in `src/real-e2e/selected-runs.test.ts`.

3. Add the first reusable scenario helper only if duplication appears after writing two surfaces:
   - Helper should copy fixture home, seed state, run sync, delete one managed file, run `status --fix`, and expose path assertions.
   - Keep helper arguments compact and typed; avoid generic assertion frameworks that hide scenario intent.

4. Add one scenario file per surface or one grouped file when surfaces share the same fixture:
   - instructions: assert managed markers/content in primary instruction files and preservation of user prose.
   - rules: assert both single-file and rules-directory outputs when supported; preserve local rules.
   - agents: assert generated subagent files exist for primary agents and local manual agent files survive.
   - hooks: assert native hook config files parse as JSON where applicable and `.devin/hooks.v1.json` remains project-local/sandboxed.
   - MCP: assert carve-out JSON/TOML outputs parse and managed missing config is repaired.

5. Add fixture data under `real-e2e/fixtures/<scenario-name>/home` only for user-owned files that must be preserved.

6. Update docs:
   - Add new scenario files to `real-e2e/SCENARIO_MAP.md`.
   - Update README only if the selected-run syntax changes.

7. Verify:
   - Run the selected real-e2e command for the new scenarios.
   - Run `npm run verify` before committing.

## Risks and mitigations

- **Risk**: Full matrix scenarios become slow. **Mitigation**: Keep one smoke path per surface in this PR, using structural assertions instead of full snapshots; leave exhaustive long-tail matrix for nightly/manual follow-up if needed.
- **Risk**: Existing delegated tools (`mcpm`, `ai-rules`) are unavailable in CI or local sandbox. **Mitigation**: Prefer native carve-out/primary deterministic outputs and skip or structurally assert delegated surfaces only when generated by agentbrew without external binaries.
- **Risk**: `status --fix` repairs only some surfaces. **Mitigation**: Treat failures as real bugs only when the surface is listed in `repair.ts`/health drift checks; otherwise add a scout task for unsupported surfaces and keep the scenario scoped to supported repair paths.
- **Risk**: A single giant helper hides behavior. **Mitigation**: Extract only path/setup repetition after scenarios make duplication obvious.

## Acceptance criteria
- `npm run test:real-e2e:selected -- instructions rules agents hooks mcp` or the documented equivalent runs the new scenarios.
- Every non-command surface has at least one deterministic real-e2e scenario.
- Each scenario asserts generated output exists and is structurally parseable where the target format supports parsing.
- Each scenario deletes one managed output and proves `agentbrew status --fix` repairs it.
- Each scenario seeds at least one user-owned file and proves it survives sync and repair.
- `npm run verify` passes.
