# Test the first run from the README

Run this test when a project claims that a new user can set up and start the
app from the README alone. Use the [run template](human-first-run-template.md)
to record each session.

## Run three sessions

1. Pick one README revision and one observable first result for the app.
   Examples include a completed first job or a verified health check.
   Set the same session limit for all three people. Use 15 minutes by
   default and keep it above ten minutes.
2. Find three people who have never used the project. Give each a clean
   machine, account, or equivalent clean environment they can use safely.
3. Give each person the README link. Let them follow links from it. Start
   the timer when they open the README. Observe or ask for a private
   time log. Let them work without coaching.
4. Stop when that person reaches the verified first result, stops, or
   reaches the agreed session limit. Record elapsed time, the outcome,
   any help, and the time and duration of each friction point.
5. Use a participant code. Keep contact details, recordings, and raw
   session notes private. Share only totals and scrubbed friction points.

## Score the result and act

- Require three verified unassisted completions. Sort their elapsed times.
  The middle time is the median. The target is at most five minutes.
- Record stopped, blocked, and coached sessions as outcomes in their own
  right. A cohort with fewer than three unassisted completions stays open.
- File every friction point that costs more than five minutes as a P1 README
  task with its observed impact and a verification step.
- Run a new cohort after a README fix. If the median still exceeds ten
  minutes after two README-fix rounds, revise the install path.
- Keep the automated clean-install checks running alongside these sessions.

Adapted from Minsky's archived user-test protocol and the
`readme-human-first-run-test` task.
